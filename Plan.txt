Codex Master Implementation Plan

Project Context

Primary writable repository:

TravPlanner

Secondary read-only reference repository:

TravelPlanner

Working branch:

codex/combine

The primary repository contains the existing Next.js frontend.

The secondary repository contains the authoritative Firebase backend architecture, shared schemas/contracts, Firestore model, callable functions, validation logic, security rules, and tests.

The objective is to turn TravPlanner into the integrated application.

The frontend design should be preserved where practical, but frontend mock-domain behavior must be adapted to the backend contracts.

Decision Rules for Ambiguity

When frontend behavior conflicts with backend behavior:

Use backend behavior.

When backend docs conflict with actual exported function code:

Use actual exported code.

When a feature exists only in frontend mocks:

Hide or downgrade it unless there is a valid backend equivalent.

When a backend field is optional:

Do not invent values unless a sensible UI default is explicitly safe.

When required information is missing from the frontend:

Add the smallest UI necessary to collect it.

When a backend feature exists but there is no good current UI location:

Prioritize the core trip workflow before adding it.
