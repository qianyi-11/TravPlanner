Step 1 — Inspect Current Startup Flow

Use Code Graph and repository inspection.

Inspect:

run-local.bat
firebase.json
lib/firebase/emulator.ts
lib/firebase/firestore.ts
lib/firebase/auth.ts
lib/firebase/functions.ts

Confirm:

run-local.bat currently starts Firebase emulators and Next.js almost at the same time.

Confirm Firestore Emulator target:

127.0.0.1:8080

Confirm Auth target:

127.0.0.1:9099

Confirm Functions target:

127.0.0.1:5001

Do not modify anything until the startup sequence is understood.

Step 2 — Fix Launcher Startup Ordering

Update run-local.bat so the sequence becomes:

build backend
start Firebase emulators
wait for emulator readiness
start Next.js
open browser

Do not start Next.js immediately after starting the emulator process.

Step 3 — Add Firestore Readiness Check

Use a real readiness check rather than only a fixed timeout.

Preferred approach:

loop until TCP port 8080 accepts connections.

Use a Windows-compatible command that does not depend on PowerShell execution policy.

Possible implementation options:

curl.exe against http://127.0.0.1:8080

or

a small Node.js TCP readiness script

Prefer the smallest reliable option already available in the development environment.

Do not assume a successful HTTP response body is required.
The goal is only to confirm the Firestore emulator is listening.

Step 4 — Check All Required Emulator Ports

Prefer waiting for all three required services:

Auth:
9099

Firestore:
8080

Functions:
5001

Do not start Next.js until all required emulator ports are reachable.

If Emulator UI 4000 is slightly delayed, it does not need to block frontend startup unless necessary.

Step 5 — Add Timeout and Failure Handling

The readiness loop must not wait forever.

Use a reasonable timeout, for example 30 to 60 seconds.

If an emulator does not become ready:

print a clear error such as:

ERROR: Firestore Emulator did not become ready on port 8080.

Then stop launcher progression.

Do not start Next.js if required emulators failed.

Keep the emulator terminal open so the user can inspect the actual Firebase error.

Step 6 — Improve Launcher Output

Print concise startup progress:

Starting Firebase emulators...
Waiting for Auth Emulator...
Auth Emulator ready.

Waiting for Firestore Emulator...
Firestore Emulator ready.

Waiting for Functions Emulator...
Functions Emulator ready.

Starting Next.js...

This should make failures obvious.

Step 7 — Harden configureFirebaseEmulators()

Inspect lib/firebase/emulator.ts.

Current risk:

configured = true

is set before all connectAuthEmulator, connectFirestoreEmulator, and connectFunctionsEmulator calls finish.

Change this so:

configured = true

is assigned only after all emulator connections succeed.

Conceptually:

if already configured, return

create app
resolve hosts
connect auth
connect firestore
connect functions
configured = true

Do not change production behavior.

Step 8 — Preserve Idempotency

Ensure configureFirebaseEmulators() remains safe if called from:

getFirebaseAuth()
getFirebaseFirestore()
getFirebaseFunctions()

Multiple calls must not reconnect emulators after successful configuration.

Do not introduce duplicate emulator connections.
